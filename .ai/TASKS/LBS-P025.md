**Technical root cause:** Browsers do not consider ordinary `http://100.x.y.z:port` an HTTPS-trustworthy/secure context, EVEN WHEN OPENED ON THAT SAME HOST and even through encrypted Tailscale. Godot 4.7.2's Web HTML shell currently rejects non-secure origins even for no-threads exports. Upstream discussion: `https://github.com/godotengine/godot/issues/124636` (opened Oct 19, 2026). Godot Web single-thread export should not need COOP/COEP headers, but the secure-origin startup check is present. **Fix hosting using trusted HTTPS**; don't disable browser security, patch generated `godot.js` to skip the check, turn on threaded export, rebuild the game unnecessarily, or recommend bypassing certificate warnings.
